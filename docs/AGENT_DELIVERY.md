# 修复交付闭环

本地交付流程：模型修改隔离工作树 → 系统验证 → 固化已验证提交 → 人工审查基础提交到修复提交的差异 → 合并该提交 → 保存交付结果 → 清理工作树与分支。

## 验证与提交

`verify_and_commit_repair` 检查 Agent 分支和基础提交，校验修改路径并暂存真实修改；记录 Git tree，执行项目已配置的验证命令，再对比 tree、文件列表和 HEAD。验证失败或验证期间源码发生变化均不创建交付提交。

通过后使用 `commit-tree` 创建固定 tree 的本地提交，以条件 `update-ref` 更新 Agent 分支。系统使用独立提交身份，不修改用户 Git 配置，不执行可能修改内容的提交钩子。待验收记录保存基础 SHA、修复 SHA、修改文件和命令结果；模型仍不能自行提交或合并。

## 审查与验收

页面显示已验证提交，差异接口使用 `base_commit..git_commit_hash`，并拒绝已被修改的工作树。页面确认请求携带已审查 SHA；旧调用方可以省略此新增字段，但服务端仍要求任务存在已验证提交并校验真实工作树。

缺少提交记录的历史待验收任务无法直接合并，需要重新执行修复验证。已有失败任务、日志和工作树不会被覆盖。

## 交付与恢复

验收先用短事务预占决策，保存仓库、分支和修复 SHA；Git 操作在事务外执行。目标仓库必须干净，Agent 工作树必须属于同一仓库、分支与 SHA 必须一致、提交必须直接基于记录的基础 SHA。

合并固定 SHA，使用系统提交身份并禁用修改内容的合并提交钩子。冲突撤销本次系统合并，目标原有提交和 Agent 修复保留。合并成功后记录 Bug 已解决及合并 SHA，再清理。

进程在合并后、结果保存前中断时，重试检查修复提交是否已经是目标分支祖先，避免重复合并。服务启动会释放中断的交付决策，使同一验收可重试。目标配置在首次交付后改变则拒绝重试，防止交付到另一个目标。

清理失败单独记录 `cleanup_pending` 和错误，Bug 保持已解决；页面可“重试清理工作树”。重试只清理，不重新合并。不强制删除脏工作树或发生变化的分支。交付期间删除任务受同一锁保护。

## 范围与限制

不推送远程、不部署、不自动验收。当前单进程服务串行处理交付；多进程部署需增加外部仓库锁。目标分支在人工等待期间出现的新提交允许正常 Git 合并；本次验证绑定修复提交，并不代表已重新验证目标分支最新组合。

验证覆盖：干净目标真实获得修复、重启后审查与确认、脏目标拒绝、审查 SHA 不一致拒绝、验证后修改拒绝、验证命令修改源码拒绝、冲突保留、清理失败及重试、合并成功后中断的幂等恢复。前端 TypeScript 与生产构建通过。
