# Pi 执行内核与修复对话

## 启用

需要 Node.js >=22.19。在 backend/pi 执行 `npm ci`，重启后端后，在「方案确认策略 → 修复执行内核」选择 Pi。模型配置沿用现有提供商。未选择时保留现有执行器，可用 AGENT_ENGINE=pi 设置部署默认值。运行或排队期间不能切换，不静默回退。

锁定官方 @earendil-works/pi-coding-agent@1.5.0，使用 Node SDK 子进程。配置保存在数据库旁 agent_runtime.json。

## 职责

Pi 管理模型请求、上下文压缩、逐消息 JSONL 会话和工具循环。Python 注册全部工具，不启用 Pi 内置 shell、文件写入或全局插件发现。现有工作树路径限制、macOS 命令沙箱、复现测试保护和提交校验保留。阶段提交成功后不执行后续工具，合并仍经原验收接口。

从修复列表或工位详情点击「进入修复」，打开独立修复工作台（`/agents/:agentId`）。消息区独立滚动，输入区保持可见，工具执行记录默认折叠；Bug 原始输入与生成的方案直接展示在单栏对话内，方案可在对话内直接选择并确认；底部输入框支持提交反馈并重新分析，也可选择仅讨论。验收继续沿用审查弹窗。工作台提供文字/截图输入、流式回复、停止按钮和原有方案/验收入口，支持刷新直达。同一 Bug 的修复轮次共享对话展示。

- 执行中：消息先落库，在执行边界交给 Agent；尚未处理时显示待处理。
- 输入区上方持续显示当前活动与计时，区分等待模型、工具执行和等待用户答复。工具活动由两个执行内核共用的包装层报告，结束或取消后清理；连接失败时前端明确提示重连。续跑开始即更新阶段，不再长期停留在“排队中”。
- 澄清问题：Agent 调用 ask_user，用户答复后继续，等待沿用阶段超时。
- 待确认、待验收或已结束：启动只读讨论，不修改源码和审批状态。
- 失败或停止后：发送“继续”“继续修复”“重试”等明确短指令，或点击“继续修复”，复用原有重试流程从中断阶段恢复；普通提问仍只读讨论。客户端重复发送不会重复排队，原任务无法复用时跳转新会话。
- 讨论期间不能批准方案或合并，停止讨论保留待确认状态。
- 调整方案或反馈未修好，使用会话内的方案/验收入口；自由聊天不作为审批授权。

API：GET/POST /api/agents/{id}/conversation；POST 使用 client_id 保证重试幂等。
GET/PUT /api/settings/agent-runtime 查看和切换内核。

## 保存与边界

对话存入独立 conversation_messages 表；截图沿用 feedback_images 内容寻址存储。
Pi 会话在数据库旁 agent_sessions/*.pi.jsonl，只读讨论使用 .chat.pi.jsonl。API Key 只通过 stdin 传递，不写入命令行、会话和模型配置文件。备份时包含上述目录。

服务中断后可通过“继续修复”按钮或聊天明确指令恢复，Pi 恢复已保存会话；没有续跑指令时不会自动继续修改。跨内核通过阶段报告与用户历史衔接。显式删除 Agent 会删除该轮对话，保留其他轮次。

当前只支持单后端进程。只读讨论不直接替代调整方案和验收动作。命令执行权限沿用原实现，本次没有增加全链路沙箱。OpenAI 兼容模型目前按文本/图片和 128k 上下文注册，特殊协议需要适配。

## 少打断的智能确认

新分析工具要求区分 `decision_questions`（问题、选项、推荐索引、影响、调查依据）、`assumptions` 和 `verification_limits`。工具校验后标记 `decision_schema_version=1`，并将真正的决策问题投影到 `open_questions`，兼容原有调用方。每个方案保存 `files` 与 `impact.categories/evidence`，风险按实际操作判断；常规技术备选按推荐顺序选择，不因数量暂停。`ask_user` 也遵循先调查、再问关键问题的边界。

新报告不使用标题关键词豁免跳过实际风险判断；强制确认模式仍生效。低置信度、无法复现、超出改动文件阈值、关键优先级和最终合并确认继续保留。实际风险仍由 Agent 根据证据评估，不等同于独立静态审计保证。

旧报告及已有待确认任务不自动重分类或放行，保留原规则；新一轮分析使用新协议。无需迁移数据库，不修改用户已保存的 always/smart/never 模式。只读讨论不替代批准，选择选项仅填写回复草稿，明确提交后才重新分析。
