# 上下文管理改造方案

状态：长期目标方案。v1 已实现证据回查、原生压缩失败保护/执行边界检查点、模型窗口配置及双内核指标日志；完整落地范围、未完成项与下一轮优化入口见 [运行说明](context-management-operations.md)。尚未切换默认内核或迁移旧任务。

## 1. 决策与目标

最终以 Pi 管理模型会话、近期消息和语义压缩；Python 负责业务状态、工具执行、证据存储、权限与提交校验。已有原生任务继续使用其创建时的内核，新任务经过验收后逐步采用 Pi。不长期维护两套独立演进的高级压缩算法。

优化目标按优先级排序：业务约束与证据可靠、可恢复、请求预算可控、任务完成质量、延迟与费用。压缩率只作为辅助指标。

模型工作上下文由四部分组成：当前任务约束与业务状态、可追溯的结构化调查摘要、近期完整交互、按需读取的证据片段。摘要允许有损，原始证据在配置的保留期内可查询；审批与阶段状态始终以 Python 数据库为准。

## 2. 当前实现与需要解决的根因

- `tool_agent.py` 用 300000 字符触发，尝试降到 150000 字符，仅替换旧的大工具结果，保留最近 6 条大结果；不处理持续累积的助手回复、工具参数和历史摘要。
- 摘要仅收到各结果前 4000 字符，合并后再截到 40000 字符。原结果在摘要成功前就已替换；失败后只留下占位。补读固定取最近 5 个文件的前 120 行。
- `repair_config.py` 中另一套压缩参数没有接入上述流程。
- 原生会话在阶段成功后保存；进程中断不能保证恢复当前轮的工具证据。用户消息被标记 delivered 与模型会话持久化没有统一恢复边界。
- Pi 已有结构化增量压缩和 JSONL 会话，但桥接把所有模型窗口写成 128000；项目尚未明确提供工具证据回查、任务状态保护和压缩质量验收。
- 当前桥接监听 `auto_compaction_end`，已安装 SDK 的相关声明与实现使用 `compaction_start` / `compaction_end`。需要按锁定版本契约适配成功、取消和失败，不能统一显示成功。

## 3. 最小职责划分

### Python：事实、证据与工具生命周期

复用当前 SQLite 和数据库旁任务存储目录。增加证据索引及必要的执行状态，不引入向量数据库、独立记忆服务或通用工作流框架。

每次工具执行记录稳定标识：任务、执行轮次、调用 ID、工具名、参数、开始/结束状态、结果引用。证据另记时间、退出码、工作树版本或相关文件哈希、完整输出的存储位置与大小。文件读取记录路径和实际行区间。

工具结果必须在现有截断发生前进入受控归档。命令输出采用流式落盘或有上限的磁盘暂存，避免在内存累积无限日志。超出保留上限时明确记录截断范围；不得宣称保存了全文。保持现有密钥禁读与沙箱边界，凭据不进入会话；产物只可由所属任务访问，生命周期随任务备份、删除和保留策略管理。

模型默认收到退出码、关键信息、有限的头尾片段及 `evidence_id`。提供一个只读的证据查询工具，支持按 ID、行区间和关键词取片段；必要时按工具、路径、时间列出任务内证据。无需重执行旧命令来恢复其历史结果。

### Pi：模型工作会话

使用锁定 SDK 的公开扩展接口管理压缩，复用其会话日志、近期消息边界和摘要机制；不修改 `node_modules`，不直接访问私有字段。若当前公开接口不足以满足候选摘要验证或预算检查，先通过小型集成验证确定适配方式或兼容版本升级，再实施；不得假设扩展接口已支持全部需求。

Python 的证据记录和 Pi 的 JSONL 各司其职：前者记录业务事实和工具结果，后者记录模型交互。不额外复制第三份完整聊天历史。通过稳定调用 ID、证据 ID、业务状态版本和压缩检查点关联。

## 4. 固定任务状态与调查摘要

### 固定状态：由系统生成并在请求前同步

包含任务目标与验收要求、当前阶段、已选方案及审批版本、受保护复现测试、当前工作树、最新待处理消息 ID、已确认的用户决策及其消息引用。直接复用现有业务数据，不允许摘要模型生成审批授权或改变校验结果。

自由聊天中的意图与约束不能全部依靠规则自动提取。最新用户消息原文保留在近期上下文；调查摘要引用对应消息 ID。用户回答的业务决策优先保存到已有决策数据，而不是仅写进自由文本摘要。

### 调查摘要：压缩时增量更新

保留目标、约束、已证实/已排除假设、改动进度、验证证据、阻塞原因、下一步。事实附证据引用；假设明确标注。测试通过须关联命令、退出码和代码版本，环境启动失败不能变成业务复现失败。

旧结论被新证据推翻时，更新当前状态并保留被替代结论的引用，不把所有历史观点不断追加。当前摘要只保留一个有效版本，历史版本仍可审计。

文件内容按实际读取区间、当前改动区间和未解决问题补入。文件哈希变化时标记旧证据属于历史版本，并按需读取当前内容；不得将旧测试结果表述为对新版本的验证。

## 5. 预算与压缩时机

模型能力配置按提供商和模型标识管理，新增可选字段，兼容现有模型列表和阶段配置。能力优先级：用户明确配置、经过核实的模型元数据、标注为估算的保守兼容值。未知模型不能仅根据名称推断窗口，也不能继续将 128k 当作已知事实。

预算定义：

`B = C - O - S`

- C：模型上下文窗口。
- O：本次最大输出预算，遵循提供商实际输入/输出限制。
- S：工具输出增长、图片估算误差和协议开销的安全余量。
- B：允许发送的输入上限，计入系统提示、工具定义、全部消息、工具参数和多模态内容。

使用可用的模型 tokenizer 或 SDK 估算，并用提供商 usage 校准。仅按当前请求与新增尾部校准，压缩后不复用旧请求的总 usage；缺失 usage 时明确标为估算。批量工具输出受本轮返回预算限制，完整证据留在归档。

首版可从输入预算约 80% 触发语义压缩、约 50%–60% 为压缩后目标开始调优；这些是待测的初始参数，不是固定最优值。较大的固定任务状态会改变可达目标，必须显式计算。

每次请求前做预算检查，不只在收到响应后检查。先将可回查的大证据外置，再在完整交互边界进行语义压缩。摘要和近期消息均按 token 分配预算，不能固定保留 N 条不等长输出。系统要求与工具调用/返回配对不可破坏。

窗口溢出最多做一次更强的压缩并重试未执行工具的模型请求；仍无法容纳时报告具体预算问题。不得无限压缩重试，也不得自动丢弃当前用户请求或扩大已配置的模型窗口。

## 6. 压缩事务与失败处理

1. 在工具结果已保存、当前工具调用已闭合的边界选择压缩范围，记录消息序号和业务状态版本。
2. 从已有摘要与新增交互生成候选摘要。不能只截取所有结果开头；工具片段必须携带操作与证据引用，尾部失败信息由工具层保留。
3. 校验候选结构、引用存在性、固定约束完整性和最终输入预算；不声称这些机械检查能证明语义完全无遗漏。
4. 原子保存有效压缩检查点，再切换模型上下文。原始会话和证据不因压缩被覆盖删除。
5. 压缩期间收到的新消息继续先落库，留在压缩截止序号之后；下一次请求纳入，终止提交前继续检查新消息。

摘要失败：保持前一个有效检查点；暂态请求错误允许有限重试。若仍可在预算内运行，可暂缓压缩；若已超预算，先做可回查的确定性输出缩减。仍不足则保留状态并明确暂停原因。禁止“摘要失败但丢弃原文继续”，也不额外启动一个每轮调用的总结模型。

## 7. 中断恢复与执行语义

工具调用按 `started → completed/failed/uncertain` 记录。结果归档成功后才能回传模型。崩溃发生在副作用完成但结果未保存的间隙时，状态只能是 uncertain；不宣称数据库与外部副作用具有原子性。

恢复时核对阶段、审批版本、工作树差异、最近工具记录和待处理用户消息。已完成工具使用已保存结果；不重复执行写文件、安装、提交或其他有副作用命令。uncertain 的操作先依据实际文件/进程/仓库状态核验，无法确定时明确阻塞。

用户消息仍以数据库记录为可靠入口。将“已进入可恢复会话”和“已处理到检查点”区分；按稳定消息 ID 去重和重放，不仅依赖当前 delivered 标志。在 Pi/宿主之间用持久化回执及启动对账处理崩溃间隙，避免承诺跨存储的 exactly-once。

普通聊天永远不能替代审批。恢复与压缩后，提交验证器重新读取数据库权威状态和待处理消息；不能信任摘要中的“用户已批准”。

## 8. 兼容与迁移

1. 先部署共享证据存储、查询、预算信息和工具执行记录，两种内核复用同一宿主工具包装层。
2. 原生内核进行必要可靠性修复：成功生成候选后才替换、引用原始证据、逐轮检查点、摘要失败保留状态。此阶段不再给原生发展第二套复杂摘要体系。
3. 完善 Pi 的模型能力、宿主状态同步、压缩事件与公开接口适配。用独立测试任务验证，尚在运行的任务不切换。
4. 为任务持久化内核归属。新任务在验收后逐步使用 Pi；全局设置只影响新任务。旧任务继续原内核，若必须迁移则显式生成带证据引用的阶段交接检查点，并保留旧会话。
5. 回滚时停止新任务采用 Pi，不把 Pi 会话隐式喂给原生执行器；Pi 已有任务继续可恢复或显式交接。

旧 API、会话文件、已有审批记录和工具签名保持兼容。新增证据查询工具与可选配置字段不要求已有调用方同时升级。原生退出维护的时间在真实数据验证后决定，不在首轮直接删除。

## 9. 可观测性与验收

前端记录压缩开始、成功、失败和取消，成功提示示例：`上下文已整理：约 82k → 36k tokens，历史工具输出可回查`。不能在失败时显示成功；token 为估算值时标明。详情展示触发原因、压缩耗时、摘要版本和证据入口，不暴露模型凭据或无限日志。

必须通过的确定性检查：

- 中文、英文、代码、大补丁、多图、无 usage 场景预算可解释；压缩后仍超预算不会直接发送。
- 输出尾部的关键错误有引用且可回查；文件变化可区分新旧证据。
- 压缩超时、取消、无效摘要、引用缺失均不替换有效检查点；连续压缩不会无限叠加摘要。
- 并行只读工具批次不破坏调用配对；新用户消息在压缩与提交期间均不丢失。
- 进程在工具开始、执行后、结果落盘后、压缩提交前后被杀死，恢复不会静默重放有副作用操作。
- 两种内核、历史会话、只读讨论和跨阶段续跑保持行为兼容；审批与复现测试保护不能被摘要绕过。
- 与锁定 Pi SDK 做契约测试，验证真实事件名、恢复行为、压缩失败和扩展接口。

任务质量采用固定的历史代表任务与故障注入对照：单次和多次压缩、环境依赖阻塞、用户纠正、停止续跑、方案反馈。记录修复验收结果、重复调查/重复提问、漏掉关键约束、总 tokens、缓存命中、耗时及压缩成本。基线与新方案使用相同模型和配置，多次运行比较，不能凭一个成功任务宣称质量提升。

发布门槛：上述确定性安全与恢复检查全部通过；代表任务无新增审批/证据回归，完成质量达到基线；成本和耗时增量在测量后确认可接受。节省比例不预先承诺。

## 10. 实施分批与对应验证

| 批次 | 交付 | 对应验证 |
|---|---|---|
| A：可靠保存 | 证据归档/查询、工具执行记录、原生检查点与失败保护 | 尾部证据回查、截断标记、崩溃注入、旧会话续跑 |
| B：统一预算 | 模型能力可选配置、输入估算、usage 校准、大输出限额 | 各类型输入预算、未知模型、溢出与批量工具结果 |
| C：Pi 集成 | 固定任务状态、结构化压缩、事件适配、消息恢复对账 | SDK 契约、连续压缩、用户纠正、审批不可提升 |
| D：迁移验证 | 任务内核归属、新任务灰度、回滚与显式交接 | 双内核兼容、对照任务质量/费用、停止恢复 |

主要改动集中在 `agent_tools.py`、`agent_runtime.py`、`tool_agent.py`、`pi_agent.py`、`bridge.mjs`、`repair_agent.py`、`conversation.py`、模型配置与数据库迁移；前端仅增加必要模型能力配置与压缩状态展示。新模块按证据存储和预算职责拆分，避免把全部逻辑继续堆入工具循环。
