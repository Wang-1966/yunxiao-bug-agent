# 上下文管理：Pi 压缩与运行记录

## 已实现

- 执行路径仅保留 Pi。模型请求、压缩触发、摘要、溢出恢复和持久化由 Pi SDK 负责；宿主使用原生压缩设置，不计算输入硬上限、触发比例或近期保留预算。
- 上下文窗口按当前提供商与模型自动解析：提供商覆盖、`backend/pi/model-context-defaults.json` 内置配置、Pi 原生目录。用户无需填写窗口；未知模型明确报告服务端配置未收录，不再读取全局 `AGENT_CONTEXT_WINDOW` 或回退为 128K。来源与渠道边界见 [默认配置说明](model-context-defaults.md)。
- 字符估算仅用于监控和实测用量对照，不阻断请求。Pi 根据模型用量决定阈值压缩，并处理服务端可识别的上下文溢出及压缩重试。
- 记录 Pi 请求（包括摘要请求）、压缩、工具执行、证据保存/回查及运行结束。压缩事件区分成功、取消、失败；真实 usage 存在时记录输入、输出及缓存 token。
- 任务内证据通过 `read_evidence` 回查。省略 ID 可列出最近 30 条证据，按 ID 支持分页和文本查询。宿主业务工具返回有界预览，Pi 原生工具保留 SDK 输出与截断说明。
- 命令输出持续排空并限制内存，最多保留 8 MiB 的头尾；单条归档文本最多 200 万字符，超限或上游截断有标记。文件记录包含可用的文件哈希。证据不是无限量全文备份。

## 数据位置

相对于配置的数据库所在目录：

```text
agent_context/<工作树名>-<路径哈希>/
  runs/<run_id>.jsonl          # 结构化指标，不含对话/工具输出正文
  evidence/<evidence_id>.json # 有界工具结果及参数、时间、文件版本等
agent_sessions/*.pi.jsonl    # Pi 的持久化消息与压缩记录
```

文件采用当前用户可读写权限。证据仅通过当前工作树范围的查询工具访问，模型不能指定归档文件路径。指标文件包含 `schema_version`、`policy_version`、`agent_id`、`run_id`、内核、提供商、模型和阶段。提供商 API Key 不写进指标；证据中的已知提供商 Key 会脱敏。证据仍可能包含业务源码或命令正文，应与原会话数据同等保管。

新运行使用策略 v2，表示上下文策略交由 Pi；历史 v1 日志、旧 Python 会话与检查点保留供审计，旧 Python 会话不再加载。报告按策略版本分组，历史 `budget_blocked` 仍可查询，新运行不产生宿主预算阻塞事件。

`run_start` 记录已有模型配置或 `pending_pi_catalog`；Pi 初始化后写入 `model_context`，包含最终 `context_window` 与 `window_source`（`configured`、`project_default` 或 `pi_catalog`）。任务日志同步显示所选模型和窗口。中转商可能限制原厂模型能力，获取模型列表时优先补入该提供商公布的窗口；管理员已有覆盖保留。

日志自动伴随新运行产生，无需启动额外监控任务。已有历史没有这些指标，不能反向伪造。重启/重新加载后端才能让新代码作用于运行；不要为了启用日志强制打断执行中的任务。

本版默认保留记录，便于比较多轮运行；不会自动删除旧证据或修改已有任务的内核。备份和清理时一起处理上述目录。保留期、全局磁盘配额及任务删除联动尚未加入本版。

## 查看与导出

从 backend 目录执行：

```sh
venv/bin/python -m src.core.context_report
venv/bin/python -m src.core.context_report --agent agent-task-xxx
venv/bin/python -m src.core.context_report --json
venv/bin/python -m src.core.context_report --root /绝对路径/agent_context
```

命令默认输出 Markdown，`--json` 输出机器可读汇总。报告不读取证据正文。可用 shell 重定向将一次报告保存到指定文件。统计按内核、提供商、模型、阶段、策略版本分组，支持同策略下多次运行对照。

主要字段：

| 指标 | 判断用途 |
|---|---|
| 压缩成功/失败/取消/跳过/拒绝与耗时 | 是否因摘要故障或反复触发增加延迟 |
| 估算缩减、历史未达目标与预算阻塞 | Pi 压缩效果及历史 v1 故障对照 |
| 实际输入 / 估算输入 P95 | 大于 1 时留意低估；没有 usage 就显示无样本 |
| 实测输入、输出、缓存 token | 用量与缓存效果，不把缺失 usage 当零成本 |
| 证据保存/回查/截断次数 | 片段预算是否过小或归档上限是否不够 |
| 相同工具与参数再次调用 | 潜在重复调查，也可能是合理复测，不能直接定性 |
| 工具结果不确定、缺少结束记录 | 取消/崩溃窗口，恢复时需要核验 |
| 运行结束状态 | 阶段提交与异常情况；不等同于最终 Bug 验收成功 |

Pi 的请求次数包括被取消的模型尝试；实际有 usage 的次数单独统计。日志尾行不完整时报告计数并跳过，不把整个报告判为不可读。没有结束记录可能表示运行仍在进行，也可能是进程崩溃。

## 下一次优化流程

1. 按同模型、同阶段和策略版本保存汇总，选取成功、失败、停止续跑、用户纠正和多次压缩任务各若干。
2. 先处理摘要失败、证据截断和未完成工具。通过 `agent_id/run_id/evidence_id` 定位真实记录，核对用户验收结果。
3. 核对模型真实窗口、Pi 的压缩事件与持久会话，使用 SDK 原生能力处理问题，避免重新加入宿主硬预算。变更策略时递增 `POLICY_VERSION`，保留历史记录用于对照。
4. 跑相同故障注入用例和代表任务。不能仅凭压缩率下降宣称质量提升；优先确保没有新增用户约束遗漏、审批绕过或中断重放。

## 明确边界

- 执行路径已统一为 Pi，上下文压缩与持久会话由 Pi 管理；agent_runtime.json 和 AGENT_ENGINE 不再参与执行选择。旧 native 会话文件不再加载，历史阶段报告、对话与证据保留。调用监控使用自托管 Langfuse，详见 ../../infra/langfuse/README.md。
- Pi 压缩受摘要模型服务和输入可缩减程度限制，不承诺任意长输入总能恢复。压缩失败保留会话，不能把失败显示成成功。
- 当前 token 算法是保守估算，图片预留 4096 tokens，并非对所有模型的精确计费。usage 用于报告校准，尚未自动学习估算系数。
- 摘要有效性由 Pi 校验，真实语义完整性仍需代表任务验收。业务审批和提交校验仍以现有 Python 校验器为准。
- 未实现跨数据库与 Pi 文件的完整消息回执事务、外部副作用 exactly-once、自动核验所有 uncertain 操作或全量业务状态重建。普通执行恢复不会自动重放已保存的工具调用；模型收到明确核验要求。
- 本次测试使用脚本模型和本地模拟 SSE 提供商，不包含付费生产模型的修复成功率结论。
