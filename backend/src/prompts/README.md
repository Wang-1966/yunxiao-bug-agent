# 提示词工程

业务提示词与执行逻辑分离，以 UTF-8 `.txt` 模板维护，无额外依赖。

- `analyze.txt`、`propose.txt`、`fix.txt`：根因分析、方案设计和实施修复。
- `styles/`：具体（`detailed`）、较简（`concise`）、极简（`minimal`）的表达规则。
- `repository*.txt`：源码工具协议、仓库上下文和修改约束。
- `vision*.txt`、`image*.txt`、`finish_reminder.txt`：截图识别和源码操作辅助提示词。

在「通用配置 → 提示词工程」选择并保存回答风格，设置复用 `data/llm_config.json` 的 `response_style` 字段。旧配置默认使用具体档；保存后后续阶段生成提示词时使用新设置，不重写历史回答或正在发送的请求。

所有档位保留现有 JSON 字段、源码依据、兼容性、风险和验证要求。具体档继续生成 2–3 个方案；较简档默认一个推荐方案，确有取舍时增加备选；极简档一个方案。长度是模型表达目标，不做字符串截断，也不限制推理或源码阅读。

模板使用 Python `string.Template` 的 `$name` 占位符，字面量 `$` 写成 `$$`，JSON 花括号无需转义。替换只执行一次，用户数据中的占位符不会被再次展开。编辑模板后下一次调用即读取新内容；保留 JSON 结构、工具协议与已有占位符，避免影响解析和执行。
