# Agent 产品设计对比分析

> 早期对照笔记。当前产品用 Pi 做工具循环与压缩，用 Python 做权限、验证和审批，不以「自研一套 Claude Code」为目标。总览见 [README](../README.md)。

## Claude Code 的设计原则

### 1. **单 Agent 迭代，无独立审查**

```
Claude Code 工作流：
User prompt → Agent 分析 → Agent 修改 → (自我检查) → 完成
                ↓ 如果不确定
              Ask user
```

**关键点**：
- **没有独立的 Review Agent**
- Agent 在工具调用中自我检查（运行测试、编译验证）
- 不确定时直接问用户，而不是进入审查循环

### 2. **Tool-based Verification > LLM Review**

```python
# Claude Code 的验证方式
1. 修改代码
2. 运行测试 (run_command)
3. 如果失败 → 看输出 → 修正 → 重新测试
4. 如果通过 → 完成

# 你们当前的方式
1. 修改代码
2. 另一个 LLM 审查代码（花费 3-5 分钟）
3. 如果驳回 → 重新修改 → 再次审查（又 3-5 分钟）
4. 循环 2-3 次
```

**差异**：
- Claude Code 依赖 **工具验证**（测试、类型检查、编译）
- 你们依赖 **LLM 审查**（成本高、速度慢、可能误判）

### 3. **Fail Fast & Iterate**

```
Claude Code：
- 小步快走，立即运行测试
- 失败了马上看输出调整
- 平均 2-3 轮工具调用就能完成一个修复

你们的 Agent：
- 大步慢走，完整分析后才提交
- 提交后等待 Review Agent 审查
- 平均 10+ 轮才完成（包括审查轮次）
```

## Cursor Compose 的设计

### 核心特点

```
1. 流式输出给用户看
   - 用户实时看到 Agent 思考过程
   - 可以随时打断："不对，你理解错了"
   
2. 多轮对话式修复
   - Agent: "我发现问题在 X，准备这样改"
   - User: "不对，应该改 Y"
   - Agent: "明白了，那我改 Y"
   
3. 无预设审查流程
   - Agent 改完就提交
   - 用户不满意再说
```

**vs 你们的设计**：
- 你们预设了 Review Agent 关卡
- 用户只能在"方案确认"和"最终确认"两个点介入
- 中间的审查循环用户完全看不到进展

## Grok Build / Windsurf 的设计

### 关键洞察

```
1. 预测性执行
   - Agent 边分析边尝试修改
   - 不等完整分析才动手
   
2. 增量验证
   - 每改一个文件就验证一次
   - 不是改完所有文件才统一验证
   
3. 用户可随时介入
   - 看到不对劲可以立即停止
   - 不需要等 Agent 完成整个流程
```

## 对比总结

| 维度 | Claude Code / Cursor | 你们的设计 | 效果差异 |
|------|---------------------|-----------|---------|
| **验证方式** | 工具验证（测试、编译） | LLM 审查 | 工具快 10x |
| **迭代模式** | 小步快走 | 大步慢走 | 前者更易调整 |
| **用户介入** | 随时可打断 | 只在固定节点 | 前者更灵活 |
| **审查机制** | Agent 自查 + 工具 | 独立 Review Agent | 后者易死循环 |
| **失败处理** | 立即重试 | 等审查轮次结束 | 前者恢复快 |
| **透明度** | 流式输出 | 阶段性报告 | 前者用户更安心 |

## 为什么独立 Review Agent 不是好主意

### 理论上的优势
- ✅ 对抗性审查提高质量
- ✅ 分工明确

### 实际中的问题
- ❌ **理解偏差**：Review Agent 不知道 Fix Agent 的上下文
- ❌ **目标冲突**：Review 追求完美，Fix 追求可行
- ❌ **死循环风险**：双方对"是否修好"的标准不一致
- ❌ **成本翻倍**：每次修复都要跑两个 Agent
- ❌ **延迟累积**：串行执行，时间倍增

### 真实案例（你们的 Agent）

```
Round 1:
Fix:    "我改了配对逻辑"
Review: "单段改标题路径未覆盖" → 驳回

Round 2:
Fix:    "我补了文字相似度匹配"
Review: "测试只断言修复前就通过的路径" → 驳回

Round 3:
Fix:    "我放开了跨类型评分"
Review: "collapseAbsorbedTextBlocks 仍未处理单段" → 驳回

用户看到的：69 分钟后才进入方案确认
```

**问题**：Review Agent 一直揪着"单段改标题"不放，但可能这根本不是用户真正遇到的场景。

## 业界共识

主流 AI coding 产品**都没有**独立的 Review Agent：

1. **Claude Code**: 单 Agent + 工具验证
2. **Cursor Compose**: 单 Agent + 用户对话
3. **GitHub Copilot Workspace**: 单 Agent + PR review
4. **Grok Build**: 单 Agent + 增量验证
5. **Windsurf Cascade**: 单 Agent + 流式反馈

**唯一的例外**：
- Devin（已倒闭）：曾经用多 Agent 架构
- 问题：速度慢、成本高、用户等不起

## 建议的改进方向

### Option 1: 去掉 Review Agent（推荐）

```python
# 简化流程
分析 → 生成方案 → 用户确认 → 修复 → 工具验证 → 用户验收
```

- 删除 `run_review()` 调用
- 依赖测试和编译来验证
- 节省 70% 时间

### Option 2: Review Agent 降级为可选

```python
# 只在特定场景启用 Review
if bug.severity == "critical" and config.enable_strict_review:
    review = await run_review(...)
    if review['refuted']:
        # 只给一次机会，不循环
        ...
```

### Option 3: 改为协作式审查（折中）

```python
# Review 不再是门禁，而是建议
review = await run_review(...)
if review['refuted']:
    # 把审查意见作为上下文给 Fix Agent
    # 但不强制重做，让 Fix Agent 自己判断
    messages.append({
        'role': 'user',
        'content': f'审查建议：{review["summary"]}（供参考，你判断是否需要调整）'
    })
```

## 成本对比

### 当前架构（带 Review Agent）

```
分析阶段：
- Fix Agent:   40 轮 × 3 分钟 = 120 分钟模型时间
- Review #1:   审查 5 分钟
- Fix Agent:   重做 20 轮
- Review #2:   审查 5 分钟
总计：150+ 分钟模型时间

Token 消耗：~500K tokens
成本：~$15/bug (Claude Opus)
时长：60-90 分钟
```

### 去掉 Review Agent

```
分析阶段：
- Agent:       30 轮 × 2 分钟 = 60 分钟模型时间
- 工具验证:    测试运行 2 分钟
- 失败重试:    10 轮
总计：70 分钟模型时间

Token 消耗：~200K tokens
成本：~$6/bug
时长：15-25 分钟
```

**节省**：60% 成本，70% 时间

## 推荐的最终架构

```
┌─────────────────────────────────────────┐
│  用户提交 Bug                             │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  Agent 快速分析 (5-10 分钟)              │
│  - 看代码、看截图                         │
│  - 边看边运行测试验证假设                 │
│  - 生成 2-3 个方案                       │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  用户确认方案 👤                         │
│  - 可以补充信息                           │
│  - 可以选择/修改方案                      │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  Agent 实施修复 (5-10 分钟)              │
│  - 修改代码                               │
│  - 实时运行测试                           │
│  - 测试失败 → 立即调整 → 再测试          │
│  - 测试通过 → 提交                        │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  用户验收 👤                             │
│  - 查看改动                               │
│  - 确认/驳回                              │
└─────────────────────────────────────────┘
```

**关键变化**：
1. ❌ 删除独立 Review Agent
2. ✅ Agent 边改边用工具验证
3. ✅ 用户是唯一的"审查员"
4. ✅ 失败快速重试，不等审查轮次
