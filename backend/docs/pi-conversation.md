# Pi 执行内核与修复对话

## 启用

需要 Node.js >=22.19。默认使用 Pi，启动脚本会准备依赖；手动启动前在 backend/pi 执行 `npm ci`。模型配置沿用现有提供商。已有 agent_runtime.json 或 AGENT_ENGINE 显式配置优先，可在「方案确认策略 → 修复执行内核」切换。运行或排队期间不能切换，Pi 异常不静默回退到 native。

锁定官方 @earendil-works/pi-coding-agent@1.5.0，使用 Node SDK 子进程。配置保存在数据库旁 agent_runtime.json。

## 职责

Pi 管理模型请求、上下文压缩、逐消息 JSONL 会话和工具循环。编码能力直接使用 SDK 原生 `read`、`edit`、`write`、`find`、`ls`、`bash`；文件分页、图片处理、批量编辑、差异和命令输出截断由 Pi 实现。Python 在执行前校验阶段权限与路径，执行后归档结果、差异、退出码和截断标记，并提供活动状态与历史证据 ID。不会将原生结果再次转换成旧工具格式。

`bash` 使用 Pi 的进程执行、超时和取消机制，通过 `spawnHook` 接入既有 macOS 命令沙箱及精简环境变量；不支持命令沙箱的平台继续不开放命令。`grep` 保留项目已有的受控实现：当前 Pi SDK 的搜索子进程不提供执行适配钩子，直接套沙箱会在遇到 `.env` 等禁读文件时导致整次搜索失败。其余宿主工具负责阶段提交、用户澄清、Bug 截图、预览和历史业务证据。native 模式保留原工具，Pi 不再注册旧的通用文件/命令工具。

工作树路径限制、分析阶段只能编辑测试、讨论只读、已有文件先读后改、复现测试保护和提交校验继续生效。阶段提交成功后不执行后续工具（包括同一轮已返回的后续调用），合并仍经原验收接口。停止时通过 SDK 取消工具并清理命令子进程；未确认完成的工具记录为结果不确定。

仓库根目录规范按 `AGENTS.override.md`、`AGENTS.md`、`CLAUDE.md` 顺序选择，结合原有任务上下文交给 Pi `DefaultResourceLoader`。项目 `.pi/skills`、`.agents/skills` 由 Pi `loadSkills` 发现并按需读取；只暴露工作树内通过路径校验的 Skills，拒绝越界符号链接。不自动加载用户全局资源、项目可执行扩展或 MCP 服务；当前没有业务需要的 MCP 配置，后续接入应复用 SDK 扩展机制。

从修复列表或工位详情点击「进入修复」，打开独立修复工作台（`/agents/:agentId`）。消息区独立滚动，输入区保持可见，工具执行记录默认折叠；Bug 原始输入与生成的方案直接展示在单栏对话内，方案可在对话内直接选择并确认；底部输入框支持提交反馈并重新分析，也可选择仅讨论。验收继续沿用审查弹窗。工作台提供文字/截图输入、流式回复、停止按钮和原有方案/验收入口，支持刷新直达。同一 Bug 的修复轮次共享对话展示。

- 执行中：消息先落库，在执行边界交给 Agent；尚未处理时显示待处理。
- 输入区上方持续显示当前活动与计时，区分等待模型、工具执行和等待用户答复。宿主工具与 Pi 原生工具都报告活动，结束或取消后清理；连接失败时前端明确提示重连。续跑开始即更新阶段，不再长期停留在“排队中”。
- 澄清问题：Agent 调用 ask_user，用户答复后继续，等待沿用阶段超时。
- 待确认、待验收或已结束：启动只读讨论，不修改源码和审批状态。
- 失败或停止后：发送“继续”“继续修复”“重试”等明确短指令，或点击“继续修复”，复用原有重试流程从中断阶段恢复；普通提问仍只读讨论。客户端重复发送不会重复排队，原任务无法复用时跳转新会话。
- 讨论期间不能批准方案或合并，停止讨论保留待确认状态。
- 调整方案或反馈未修好，使用会话内的方案/验收入口；自由聊天不作为审批授权。

API：GET/POST /api/agents/{id}/conversation；POST 使用 client_id 保证重试幂等。
GET/PUT /api/settings/agent-runtime 查看和切换内核。

## 保存与边界

对话存入独立 conversation_messages 表；截图沿用 feedback_images 内容寻址存储。
Pi 会话在数据库旁 agent_sessions/*.pi.jsonl，只读讨论使用 .chat.pi.jsonl。API Key 只通过 stdin 传递，不写入命令行、会话和模型配置文件。备份时包含上述目录。

服务中断后可通过“继续修复”按钮或聊天明确指令恢复，Pi 恢复已保存会话；没有续跑指令时不会自动继续修改。跨内核通过阶段报告与用户历史衔接。显式删除 Agent 会删除该轮对话，保留其他轮次。

当前只支持单后端进程。只读讨论不直接替代调整方案和验收动作。命令执行权限沿用原实现，没有增加全链路沙箱。OpenAI 兼容模型按文本/图片注册，上下文窗口使用提供商模型配置或项目默认预算；特殊协议需要适配。原生 `find` 依赖 fd，Pi 优先使用已安装工具，缺失时由 SDK 下载；离线部署请预装 fd 和 ripgrep。

在 backend 执行：

```sh
venv/bin/python -m pytest tests/test_pi_runtime.py tests/test_context_management.py tests/test_conversation.py tests/test_agent_harness.py -q
```

真实 SDK + 本地模拟 SSE 模型验证原生工具、批量编辑、图片、截断、阶段权限、证据归档、真实复现由失败转为通过、停止清理、阶段结束、会话恢复与凭据不落盘；同时回归 native 内核。测试禁止 SDK 隐式下载，fd 不可用时验证其明确错误反馈。
不调用付费模型，也不将集成测试视为 Bug 修复成功率提升的证据。

## 少打断的智能确认

新分析工具要求区分 `decision_questions`（问题、选项、推荐索引、影响、调查依据）、`assumptions` 和 `verification_limits`。工具校验后标记 `decision_schema_version=1`，并将真正的决策问题投影到 `open_questions`，兼容原有调用方。每个方案保存 `files` 与 `impact.categories/evidence`，风险按实际操作判断；常规技术备选按推荐顺序选择，不因数量暂停。`ask_user` 也遵循先调查、再问关键问题的边界。

新报告不使用标题关键词豁免跳过实际风险判断；强制确认模式仍生效。低置信度、无法复现、超出改动文件阈值、关键优先级和最终合并确认继续保留。实际风险仍由 Agent 根据证据评估，不等同于独立静态审计保证。

旧报告及已有待确认任务不自动重分类或放行，保留原规则；新一轮分析使用新协议。无需迁移数据库，不修改用户已保存的 always/smart/never 模式。只读讨论不替代批准，选择选项仅填写回复草稿，明确提交后才重新分析。
