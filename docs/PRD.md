# 云效 Bug 修复 Agent - 产品需求文档 (PRD) v2.0

> **当前产品形态以 [README](../README.md) 为准。** 本文是早期需求稿。实现上已统一 Pi 执行内核，前端开发端口为 3001，并增加修复工作台、项目预览、逐项验收和可选 Langfuse。下列页面名称与「设置页」划分已部分过时。

## 一、产品概述

### 1.1 产品定位
云效 Bug 修复 Agent 是一个基于 Web UI 的自主 bug 修复系统，支持多 agent 并发工作。用户通过可视化界面管理 bug 修复流程，实时查看所有 agent 的工作状态。

### 1.2 目标用户
- 需要处理大量云效 bug 的开发人员
- 希望 AI 辅助完成 bug 分析和修复，但保留决策权的程序员
- 追求代码质量，不满足于快速修复方案的工程师
- 需要同时修复多个 bug 以提高效率的团队

### 1.3 核心价值
- **解放时间**：多个 agent 并发工作，大幅提升效率
- **保证质量**：追求最优方案而非最快修复
- **保留控制**：用户通过 UI 手动控制修复流程和关键决策
- **完整验证**：确保修复不影响其他功能
- **实时可见**：通过 Web UI 实时查看所有 agent 状态

## 二、功能需求

### 2.1 核心功能

#### 功能 1：Web UI 界面
**描述**：现代化的 Web 界面，用于管理所有 bug 修复工作

**主要页面：**

1. **Dashboard（仪表盘）**
   - Bug 统计卡片（总数、按优先级分布、按状态分布）
   - 活跃 Agent 列表（正在工作的 agent）
   - 最近修复历史
   - 快速操作按钮

2. **Bug 列表页**
   - 表格展示所有云效 bug
   - 支持筛选（优先级、状态、负责人）
   - 支持搜索（标题、描述）
   - 支持排序
   - 操作按钮：
     - 查看详情
     - 启动 Agent 修复
     - 批量选择修复

3. **Bug 详情页**
   - Bug 完整信息展示
   - 修复历史时间线
   - Agent 工作日志
   - 相关代码变更
   - 测试结果

4. **Agent 监控页**
   - 所有 agent 的实时状态
   - 每个 agent 的当前工作阶段
   - 进度条和阶段指示器
   - Agent 工作日志流
   - 操作按钮：
     - 暂停/恢复
     - 停止
     - 查看详情

5. **模型与通用配置 / 方案确认策略 / 项目与仓库**
   - OpenAI 兼容提供商、阶段模型（分析 `analyze`、修复 `fix`）
   - 云效连接（界面保存优先于 `.env`）
   - 仓库、验证命令、预览启动命令
   - 方案确认模式 always / smart / never

6. **修复工作台**（`/agents/:agentId`）
   - 单栏对话、方案选择、活动状态、停止与继续修复
   - 验收仍走审查弹窗；闲聊不批准合并

**优先级**：P0（必须）

#### 功能 2：多 Agent 并发系统
**描述**：支持同时运行多个 agent，并发修复多个 bug

**核心特性：**
- **并发控制**
  - 最多同时运行 N 个 agent（默认 3，可配置）
  - 任务队列管理
  - 自动分配空闲 agent
  
- **隔离机制**
  - 每个 agent 独立的工作空间（git worktree）
  - 避免文件冲突
  - 独立的状态管理
  
- **任务调度**
  - 按优先级自动分配
  - 支持手动指定 bug 给特定 agent
  - 失败自动重试或转人工
  
- **实时同步**
  - WebSocket 推送 agent 状态更新
  - 实时进度展示
  - 日志流式输出

**优先级**：P0（必须）

#### 功能 3：云效集成
**描述**：连接云效平台，获取和管理 bug
- 自动同步云效 bug 列表（定时刷新）
- 获取 bug 详细信息
- 更新 bug 状态
- 添加评论和修复说明
- 支持按优先级、状态筛选

**优先级**：P0（必须）

#### 功能 4：Bug 分析流程
**描述**：深度分析 bug 的根本原因
- 解析 bug 描述，提取关键信息
- 定位相关代码文件
- 分析业务逻辑和数据流
- **如果不确定根因**：
  - 在 UI 中显示"需要添加日志"
  - 提出日志添加位置
  - 等待用户运行并提供日志
  - 基于日志进一步分析
- 输出根因分析报告（在 UI 中展示）

**优先级**：P0（必须）

#### 功能 5：方案设计
**描述**：提出最优修复方案
- 设计多个可行方案
- 评估每个方案的优劣
- 推荐最优方案（不是最快方案）
- **在 UI 弹窗中展示方案对比**
- 等待用户选择方案
- 支持用户添加自己的修改意见

**优先级**：P0（必须）

#### 功能 6：修复实施
**描述**：实现修复方案
- 修改相关代码文件
- 添加必要的单元测试
- 添加集成测试（如需要）
- 更新相关文档和注释
- 生成 git commit
- 在 UI 中显示变更摘要

**优先级**：P0（必须）

#### 功能 7：修复验证
**描述**：全面验证修复结果
- 运行相关单元测试
- 运行集成测试
- 检查是否影响其他功能
- 测试边界条件
- **如果验证失败**：
  - 在 UI 中显示失败原因
  - 提供重新分析或添加日志选项
  - 不猜测问题
- 输出验证报告（在 UI 中展示）
- **等待用户最终确认**

**优先级**：P0（必须）

#### 功能 8：状态持久化
**描述**：保存所有 agent 和 bug 的状态
- 每个 agent 的当前工作状态
- Bug 修复历史
- 决策记录
- 支持系统重启后恢复
- 支持手动导出状态

**优先级**：P0（必须）

#### 功能 9：实时通知
**描述**：关键事件的实时通知
- Agent 需要决策时弹窗提醒
- Bug 修复完成时通知
- 修复失败时告警
- 浏览器通知 + 页面内通知
- 可配置通知级别

**优先级**：P1（重要）

#### 功能 10：LLM 配置管理
**描述**：支持配置不同的 LLM 后端来驱动 Agent

**核心特性：**
- **多 LLM 支持**
  - Claude Opus 5（官方 API）- 理解能力最强
  - Grok 4.7（中转站 API）- 性价比高
  - GPT-4（OpenAI API）- 备选方案
  
- **灵活配置**
  - 全局默认模型
  - 不同阶段用不同模型（分析用 Claude，修复用 Grok）
  - API Key 安全存储
  - 中转站 URL 配置
  
- **成本优化**
  - 简单任务用便宜的模型
  - 复杂分析用强大的模型
  - 实时显示 token 消耗
  
- **测试和验证**
  - 测试 API 连接
  - 显示可用模型列表
  - 错误提示和重试

**配置示例：**
```yaml
默认模型: Grok 4.7
阶段配置:
  分析根因: Claude Opus 5  (需要强理解能力)
  设计方案: Grok 4.7        (生成方案)
  实施修复: Grok 4.7        (写代码)
  验证修复: Claude Sonnet 4 (快速验证)
```

**优先级**：P0（必须）

### 2.2 扩展功能（后期规划）

#### 功能 11：批量操作
**描述**：批量管理 bug
- 批量选择 bug
- 一键启动多个 agent 修复
- 批量更新状态
- 批量导出报告

**优先级**：P2（期望）

#### 功能 11：智能推荐
**描述**：AI 推荐下一步操作
- 根据历史数据推荐优先修复的 bug
- 推荐最佳并发数量
- 推荐修复策略

**优先级**：P2（期望）

## 四、界面设计

### 4.1 技术栈

**前端：** React 18 + TypeScript、Ant Design 5、Zustand、Axios、WebSocket、Vite（开发端口 3001）。

**后端：** FastAPI、LangGraph（仅阶段编排）、Pi 执行内核、SQLite、可选 Langfuse。

### 4.2 页面结构

```
/                       Dashboard（仪表盘）
/bugs                   Bug 列表页
/bugs/:id               Bug 详情页
/agents                 Agent 监控页
/agents/:id             Agent 详情页
/settings               设置页
  /settings/llm         - LLM 配置
  /settings/yunxiao     - 云效配置
  /settings/agents      - Agent 配置
  /settings/notification - 通知配置
```

## 五、非功能需求

### 5.1 性能要求
- 页面加载时间 < 2 秒
- WebSocket 消息延迟 < 100ms
- 支持同时运行 3-5 个 agent
- 单个 bug 修复时间：5-30 分钟

### 5.2 可靠性要求
- 状态持久化，支持系统重启恢复
- Agent 崩溃自动重试
- 网络断开自动重连
- 数据备份机制

### 5.3 可用性要求
- 直观的 UI 设计
- 响应式布局（支持不同屏幕尺寸）
- 友好的错误提示
- 完整的操作指引

### 5.4 扩展性要求
- 支持增加并发 agent 数量
- 支持扩展到其他 bug 平台
- 支持自定义修复策略
- 插件系统（后期）

### 5.5 安全性要求
- 云效 API Token 安全存储
- 用户认证（后期）
- 操作权限控制（后期）
- 代码变更审计日志

## 六、成功指标

### 6.1 核心指标
- Bug 修复成功率 > 80%
- 修复质量（无新增 bug）> 95%
- 多 agent 并发效率提升 > 2x（相比单 agent）
- 用户决策点 < 3 个/bug

### 6.2 用户满意度
- 比手动修复节省时间 > 60%
- 用户认可修复方案质量 > 90%
- UI 操作满意度 > 85%
